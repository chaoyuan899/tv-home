# TCL 55D6 Android 5.1 adaptation

The user selected adapting mihirgupta0900/tv-home after comparing existing launchers and the larger tinulica fork. Preserve the original native Java wallpaper, clock, dock and D-pad UI on Android 5.1.1 / API 22 / ARMv7. Additional tinulica features are a later phase.

Approach: remove newer API dependencies where an old equivalent suffices, include ordinary launcher apps, provide TCL settings/source fallbacks and an APK that can be opened without replacing Home. Keep the original package ID for minimal divergence. Use Chinese UI resources when the device locale is Chinese. Native framework only; no new runtime dependency.

The alternative of moving the entire tinulica UI was rejected for complexity and unsupported preview features. Existing Luncher/Mega were considered; the user explicitly selected this fork.

Acceptance: APK installs and launches on the real API 22 TV; wallpaper and clock render; D-pad reaches dock, grid and controls; ordinary apps appear; settings and source picker launch; returning works without crashes. Preserve original launcher until manual launch passes. Home takeover must have a recorded original component and tested restoration. No root, flashing, factory reset, system app uninstall or unrelated debloating.

No TV identifiers, IPs, app inventories, ADB keys, signing keys or screenshots are committed. The public documentation records model and generic recovery instructions only. Reboot validation is reported separately if not performed.

Device findings changed the Home implementation: the firmware rejects any HOME intent declaration with a certificate error. Use an ordinary launcher app plus an opt-in AccessibilityService limited to window-state events from com.tcl.cyberui. Exact MainActivity match, no screen-content access and no key filtering. BOOT_COMPLETED opens the app only with both preference and service authorization. Keep original Home enabled, use explicit self-targeted PendingIntent for API 22 Home transitions, and provide UI opt-out plus a shell-only recovery activity which turns off redirect (vendor rejects pm disable even for user apps).

API 22 native text-shadow rendering crashed in libRScpp/RenderThread under repeated refresh; omit text blur and raised shadows on API 22. TCL returns a TvInputManager with a null backing service; catch this optional service failure and keep the vendor picker accessible.
